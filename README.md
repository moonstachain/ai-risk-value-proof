# AI Risk Value Proof｜风险减量账本 · 学员企业解决方案

> 基于「原力战略三部曲」为学员企业重构的客户呈现、销售转化、交付验证与系统沉淀仓库。

---

## 0. 一句话北极星

**不是再卖一个安全信息化系统，而是帮助客户把“风险到底有没有下降”变成一套可看见、可验证、可汇报、可复制的价值证明系统。**

对外主表达：

```text
风险降没降，一本账说清楚。
```

对内方法论表达：

```text
风险点本体 × AI 研判 × 五动作闭环 × 价值账本 = 安全价值证明系统
```

## 1. 原力战略定位

本仓库不是一个普通项目资料夹，而是一个 **B→C 回写型创业资产仓**：

```text
客户项目结果
  → 原力创业判断
  → 客户可呈现方案
  → 90天验证包
  → 交付台账与证据链
  → 方法论 / 页面 / Codex 任务
  → 下一轮销售与交付复用
```

对应《原力战略三部曲》：

| 维度 | 本仓任务 | 输出 |
|---|---|---|
| A 轴：我是谁 | 学员的原力是复杂安全现场翻译与系统化交付 | `strategy/01-origin-force.md` |
| B 轴：怎么赚钱 | 从“大系统”转为“风险减量账本 + 90天验证包” | `strategy/02-business-design.md` |
| C 轴：如何复利 | 每次项目结果回写为方法论、模板、页面、交付资产 | `strategy/03-os-backwrite.md` |

## 3. 第一阶段交付目标

### 3.1 给客户看的

- 一页讲清：为什么不是再上一套系统，而是从“风险点本体”开始。
- 一页讲清：90天如何验证价值。
- 一页讲清：客户需要配合什么、能拿到什么。
- 一个高审美 HTML 门户，能够用于首次沟通、复盘和内部转述。

### 3.2 给学员用的

- 能直接用于客户拜访的销售叙事。
- 能拆成 PPT / 飞书 / Word 的方案正文。
- 能指导团队交付的原子级任务清单。
- 能持续沉淀项目结果的证据边界与数据结构。

### 3.3 给 Codex 用的

- 明确页面、数据、交付、模板的下一步开发任务。
- 明确哪些是示例数据，哪些必须接真实台账。
- 明确仓库如何从静态方案升级为可运行的风险减量账本。

## 4. 当前版本核心判断

1. **客户不先买 AI 的先进性，客户先买少出事、少蹲守、少背锅、说得清。**
2. **第一产品不是“大而全平台”，而是“90天风险减量验证包”。**
3. **第一场景必须小，但颗粒度必须深：从主官体征一路下钻到风险点、责任链、设备与信号源。**
4. **真正的壁垒不在页面，而在风险点本体、规则库、证据链、交付模板和回写机制。**
5. **每个项目都必须回写为下一轮更强的销售包、交付包、案例包和方法论资产。**

## 5. 使用方式

打开：

```text
docs/index.html
```

客户沟通顺序：

```text
先讲真问题 → 再讲风险点本体 → 再讲90天验证 → 再讲价值账本 → 最后讲年度复制
```

学员内部推进顺序：

```text
先补事实边界 → 再选试点场景 → 再建本体台账 → 再跑闭环事件 → 再出风险减量账本
```

## 6. 事实边界

本仓库当前包含策略重构、示例页面和方案模板。所有客户名称、点位数据、设备在线状态、项目金额、验收结果和可公开案例，正式对外前必须由学员或客户提供授权与核验材料。

推荐对外口径：

```text
页面中的样例用于说明方法、结构和交付方式；正式实施以客户真实台账、设备平台、检查记录和项目验收数据为准。
```
