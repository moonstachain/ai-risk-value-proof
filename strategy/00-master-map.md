# 00｜原力战略总图：风险减量账本

## 0. 总裁决

这个仓库的目标，不是继续包装一个复杂系统，而是把学员已有项目经验升级为一套可销售、可验证、可交付、可复利的客户解决方案。

```text
旧入口：价值证明系统
问题：概念厚重，客户第一眼不易转述

新入口：风险减量账本
第一产品：90天风险减量验证包
底层方法：风险点本体化治理
长期资产：可复用的交付与证据系统
```

一句话：

```text
风险降没降，一本账说清楚。
```

---

## 1. 三轴结构

### A 轴：我是谁

学员的不可复制能力不是“会做页面”或“会讲概念”，而是：

```text
复杂现场翻译能力
= 任务 → 需求 → 系统 → 价值 → 证据
```

她能把多部门、多场景、多数据、多角色的复杂现场，翻译成可上线、可验收、可汇报、可复制的系统结构。

### B 轴：我怎么赚钱

从“大平台销售”改成三层产品梯度：

```text
入口产品：风险减量诊断会
成交产品：90天风险减量验证包
扩展产品：年度风险减量账本 / 风险点本体平台 / 智能体能力包
```

客户先买验证，再买平台；先买一个场景的闭环，再买全域扩展。

### C 轴：如何越做越强

每一次客户项目都必须沉淀为五类资产：

```text
1. 风险点本体台账
2. 规则与阈值库
3. 闭环事件证据链
4. 客户汇报价值账本
5. 下一次销售与交付模板
```

## 2. 原力创业四关

| 关卡 | 本项目问题 | 战略裁决 | 交付物 |
|---|---|---|---|
| B1 原力借势 | AI、数据资产、风险治理都进入同一窗口 | 借势“从系统建设到价值证明”的迁移 | 趋势叙事与客户决策旅程 |
| B2 品类独创 | “价值证明系统”太厚重 | 对外品类压缩为“风险减量账本” | 客户一页纸与首页 HTML |
| B3 模式升维 | 大系统销售周期长 | 第一成交产品变成“90天验证包” | 90天路径与交付清单 |
| B4 壁垒锁定 | 项目结果容易一次性消耗 | 把项目回写为本体、规则、证据、模板和案例 | OS 回写机制与仓库结构 |

## 3. 客户决策旅程

```text
怀疑：是不是又要上系统？
触动：这些痛点确实说中了。
理解：风险点本体这套逻辑能讲通。
认可：一个场景能跑通，就能证明价值。
买单：先做90天验证，风险可控、结果可汇报。
```

## 4. 系统架构一屏图

```text
客户真问题
  ↓
风险点本体：对象 × 关系 × 动作 × 时空
  ↓
五动作闭环：建档 → 监测 → 研判 → 预防 → 回写
  ↓
一号位驾驶舱：体征 → 台账 → 风险点 → 设备/信号源
  ↓
风险减量账本：覆盖 / 响应 / 复用 / 传承
  ↓
年度复制：第二场景 / 第二区域 / 第二客户
```

---

## 5. 当前超级杠杆点

```text
选择一个客户最有压力、数据最容易接入、责任链最清晰的试点场景；
用90天把它的风险点本体做实到设备级；
跑通3-5条闭环记录；
最后形成一份客户能内部汇报的风险减量账本。
```

这就是第一块可成交、可验证、可复用的样板。
