# 03｜C轴：从一次项目到复利系统

## 0. 核心原则

这个仓库不能只是方案存档。它要把每一次沟通、试点、交付和复盘，都沉淀成下一次更好用的资产。

```text
一次项目 → 一组证据 → 一套模板 → 一个系统 → 下一次更强
```

---

## 1. 原力 OS 四件事

| 模块 | 本仓含义 | 输出位置 |
|---|---|---|
| 一纸文脉 | 为什么客户现在需要风险减量账本 | `strategy/` |
| 一个大脑 | 事实、规则、台账、口径、案例 | `schemas/` 与后续 `data/` |
| 一张地图 | 客户旅程、产品梯度、交付路径 | `docs/index.html` 与 `solution/` |
| 一条链路 | 可持续执行的任务链 | `codex/TASKS.md` |

---

## 2. 每次项目后必须回写

```text
1. 客户画像
2. 试点场景
3. 风险点清单
4. 四要素建模卡
5. 信号源接入情况
6. 闭环记录
7. 客户认可原话
8. 价值指标变化
9. 下一次复制建议
```

---

## 3. 复利资产分层

```text
L1 方法论资产：风险点本体、五动作闭环、风险减量账本
L2 销售资产：客户旅程页、一页纸开场、诊断问卷
L3 交付资产：台账模板、建模卡、闭环台账、价值账本
L4 数据资产：风险点结构、规则结构、记录结构、指标结构
L5 壁垒资产：场景规则库、案例库、能力包、伙伴手册
```

---

## 4. 仓库演化路线

```text
v0.1 方案仓：客户方案、HTML 门户、90天验证包、事实边界
v0.2 交付仓：试点模板、周报模板、验收模板
v0.3 产品仓：本地风险点台账、下钻、导出和报告生成
v1.0 OS仓：销售、交付、数据、页面和智能体任务一体化
```

---

## 5. 每周节奏

```text
周一：更新沟通记录和试点阻塞
周三：更新风险点台账与闭环记录
周五：生成本周风险减量摘要
月底：输出月度价值账本与复制建议
```

---

## 6. 禁止事项

```text
不把示例数据说成真实数据。
不只做页面、不做闭环。
不只做项目、不沉淀方法论。
不一开始追求大而全。
不跳过事实边界。
```
